# 📌 Руководство по работе с Git и версионированием DriftWM (Linux Mint Edition)

Данный документ содержит правила выгрузки кода, ведения документации и обязательные проверки перед отправкой изменений в репозиторий.

---

## 🚀 1. Куда выгружать код (Репозитории и Remotes)

Наш проект является официальным форком оригинального DriftWM. В системе настроены два удаленных репозитория:

- **`origin` (Основной репозиторий форка)**:  
  `https://github.com/DirtyPills/driftwm.git`  
  *Сдаем все изменения, доработки и коммиты сюда.*
- **`upstream` (Оригинальный DriftWM для Arch Linux)**:  
  `https://github.com/malbiruk/driftwm.git`  
  *Используется для подтягивания обновлений из оригинала.*

### Ветка и Авторство:
- **Основная ветка**: `main`
- **Автор коммитов**: `duke16bit`  
  *(Перед коммитом убедитесь, что имя задано: `git config user.name "duke16bit"`)*

## 📝 2. Правила ведения документации (README.md и docs)

При добавлении новых функций, исправлении багов или изменении конфигураций соблюдайте следующие правила:

1. **Аккуратно дополнять, а не удалять**:
   - Новое описание добавленных/исправленных фичей должно органично встраиваться в `README.md` и соответствующие документы в `docs/`.
   - **СТРОГО ЗАПРЕЩЕНО** ломать, стирать или перезаписывать существующее описание оригинального DriftWM и ранее созданных компонентов Linux Mint.
2. **Структура описания изменений**:
   - Изменения форка описываются в блоке `🌿 DriftWM — Сборка под Linux Mint (Fork by @duke16bit)`.
   - Если добавляется новый виджет или модуль — обязательно создавайте для него отдельный документ в `docs/` (по аналогии с [docs/recent-panel.md](docs/recent-panel.md)).
3. **Проверка путей**:
   - При описании файлов и конфигов указывайте относительные пути проекта (`extras/config.toml`, `extras/widgets/...`), избегая жесткой привязки к локальным папкам конкретного пользователя.

## 🔍 3. Обязательное ревью перед коммитом и пушем

Перед выполнением `git commit` и `git push` **ОБЯЗАТЕЛЬНО** провести проверку по чек-листу:

### Чек-лист проверки (Pre-Commit & Pre-Push Review):

1. **Проверить статус файлов**:
   ```bash
   git status
   ```
   Убедитесь, что в индекс попадают только целевые исходные файлы, скрипты и документация.

2. **Проверить отсутствие мусорных и приватных данных**:
   Убедитесь, что в гит **НЕ попадают**:
   - Логи работы (`*.log`, `/log`)
   - Сохраненные сессии и истории (`recent_history.json`, кэш буфера обмена)
   - Временные файлы и скомпилированный кэш Python (`__pycache__`, `*.pyc`, `.venv`)
   - Скомпилированные бинарники Rust (`target/`, `result`)
   - Приватные ключи, токены или пароли.

3. **Проверить diff изменений**:
   ```bash
   git diff
   ```
   Убедитесь, что нет случайно измененных строк, отладочных `print`/`console.log` или сломанных форматов.

4. **Выполнить коммит и отправить на GitHub**:
   ```bash
   git add .
   git commit -m "feat/fix: понятное описание сделанного"
   git push origin main
   ```
